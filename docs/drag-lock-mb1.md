# MB1ドラッグ保持：純正トラックボール試験版

対象：`feat/drag-lock-mb1-stock`。既存のGT1〜3・ST・Vial Override・ホイール対策を維持し、左ボタンだけの保持を追加した試験版です。公開版・COROPIT版は変更しません。

## 使い方

1. 現在の設定をVialから `.vil` に保存します。
2. このブランチの成功したActionsのArtifactsから、`roBa_RMK_GT_DragTest-central.uf2` を右、`roBa_RMK_GT_DragTest-peripheral.uf2` を左へ書き込みます。
3. コピーエラーがないか確認し、USBを接続し直して入力とVial認識を確認します。必要なら保存した `.vil` を読み戻します。
4. Vialを再接続し、ユーザタブの **DD+** と **DD-** をそれぞれ好きなキーへ割り当てます。初期配置は空です。
5. カーソルを対象へ合わせ、**DD+をタップ → トラボで移動 → DD-をタップ**してドロップします。

| 表示 | 動作 |
|---|---|
| DD+（DD_ON） | 左ボタンの保持を開始。キーを離しても維持 |
| DD-（DD_OFF） | DDによる左ボタンの保持を解除 |

同じDD+を繰り返し押しても解除にはなりません。DD-で解除します。
レイヤー指定は不要で、割り当てが有効な位置から使えます。MB2以降のドラッグ保持は今回の対象外です。

通常の左クリックとは保持状態を別に管理しています。DD中に通常クリックを押して離しても、DDは継続します。通常の左ボタンを物理的に押したままDD-を押すと、DDだけ解除し、物理ボタンは離すまで保持します。

USB／BLEの出力先変更、BLEプロファイル変更、切断でDDを解除し、再接続先へ持ち越しません。接続されていないときのDD+では保持を予約しません。

## 実機で確認すること

- DD+を離しても、アイコン移動や文字範囲の選択を続けられる。
- トラボを止めてから再び動かしても継続し、DD-でドロップする。
- DD中に通常クリックを押して離しても継続する。解除後の普通のクリックも正常。
- STやエンコーダーのホイール操作でもボタン状態が意図せず解除されず、ホイールが暴走しない。
- GT1〜3、通常入力、TD、マクロ、Overrideが従来どおり動く。
- DD中にUSB／BLEを切り替えたり切断・再接続しても、保持が復活しない。

切断後の相手への解放通知の到達は保証できないため、実機では再接続後の状態も確認してください。

## 実装とソフトウェア検証

- 新しいUserコード14／15を追加。BLE・CLR_PEER・GT/STの番号は変更しない。
- DDの保持は接続状態のロックと同期する揮発状態。Vial設定／フラッシュの形式や依存バージョンは変更しない。
- 通常のMB1状態を変更せず、最終送信時に全マウスレポートへDDのビットを合成する。トラボ・ST・エンコーダーの各処理は既存のまま。
- 送信キューの満杯で待機した場合は、再開時のDD状態を再取得する。解除前に組み立てたレポートでDDを再開しない。
- 出力先変更時、古い送信キューを消してキーボードとマウスの解放レポートを用意する。
- マウス条件を使うFork判定にもDD状態を反映する。通常の修飾キーOverrideは変更しない。

7件の追加ライブラリ試験で、実際のKeyboard・PointingProcessor・USB／BLEの出力キューを使い、押下・解放、通常クリックとの共存、移動／スクロール／エンコーダー、接続切替、キュー待ち中の解除を確認する。
別のホスト試験では、実際のVial通信からDD+／DD-を配置し、Keyboard・GT監視・トラボ処理を同時に動かして、DD中のSTとGT3組の出力を確認する。

ソフトウェア試験とビルドの成功は、実機のドラッグ成立を意味しません。この版は実機確認前の試験版です。
